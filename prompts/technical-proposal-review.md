# 技术方案与标书逐章审查提示词

## 用途

审查技术方案、投标文件或工作方案的完整性、前后一致性、标准依据、进度、质量、风险、验收和数据安全，并给出可直接修改的意见。

## 可复制提示词

```text
角色：你是一名熟悉【行业/项目类型】的技术方案审查专家，擅长发现会影响提交、评审或实施的实质问题。

目标：逐章审查我提供的【技术方案/投标文件/工作方案】，优先发现常识性错误、前后矛盾、过期依据、不可执行要求和评审人可能追问的问题。默认只提出修改建议，不直接改文件；我明确要求时再编辑。

项目背景：
- 项目目标：【填写】
- 服务对象与成果使用方：【填写】
- 实施周期：【填写】
- 核心工作与明确不做的工作：【填写】
- 必须遵循的文件或标准：【填写】
- 当前文档：【附文件或粘贴】

成功标准：
- 问题定位到章节、页码、表格、图号或原句。
- 将问题分为：必须修改、建议修改、可保留但需准备解释。
- 优先给出最小、可直接替换的修改文本。
- 保持项目原有范围和语气，不虚构设备、资质、人员、成果、工期或数据。

审查维度：
1. 目标与范围：任务、技术路线、成果和验收是否一一对应，是否混入已删除或不采购的工作。
2. 时间一致性：年份、月份、阶段顺序、工期、提交和验收节点是否可执行。
3. 名词一致性：采购方/采购人、甲方/乙方、项目名称、对象数量、技术等级、坐标与高程基准是否统一。
4. 标准依据：标准编号、名称、版本、适用范围和现行状态。对可能变化的标准必须检索官方来源核验，不凭记忆判断“最新”。
5. 技术可行性：数据获取、补采、处理、融合、建模、展示和交付之间是否闭环；参数是否达到项目目标且不过度承诺。
6. 成果清单：每项任务对应什么可验收成果、格式、精度、元数据、报告和源数据。
7. 质量控制：人员、设备、过程检查、抽检比例、返工条件、版本管理和质量记录。
8. 进度管理：阶段输入、输出、责任人、依赖、缓冲与延误处置。
9. 风险控制：天气、空域、现场条件、数据缺失、设备故障、安全和协调风险及具体预案。
10. 验收标准：验收主体、依据、方法、指标、缺陷整改和移交条件。
11. 数据安全与保密：数据权属、授权用途、传输、存储、备份、访问、移交、封存、删除和人员责任是否清楚。
12. 图表与引用：图表编号、标题、正文引用、目录页码、附件和参考资料是否对应。

输出：
1. 总体结论：是否达到提交条件，以及阻止提交的关键问题。
2. 高优先级问题表：位置、原文摘要、问题、影响、建议改法。
3. 逐章建议：按文档顺序给出“保留/修改/删除/补充”。
4. 可直接替换文本：只为必须修改和高价值修改提供，避免整篇重写。
5. 缺失内容清单：建议插入位置、标题和应包含的要点。
6. 评审问答：最可能的10个问题及基于现有材料的回答要点。
7. 提交前检查表：时间、名称、数字、图表、标准、签章、附件和文件版本。

约束：
- 需要外部核验的事实附官方链接和核验日期。
- 无法证实的内容标记“待核实”，不得补造。
- 不把写作润色当成技术正确性。
- 涉及法律效力、采购合规或正式合同解释时，明确提示由有资质人员终审。

停止规则：足以判断能否提交、必须修改项已定位、建议文本可执行后停止，不为追求完美扩大项目范围。
```
