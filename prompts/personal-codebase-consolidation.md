# 个人代码工具库整合提示词

## 用途

调查多个散乱的脚本和项目目录，按真实用途制定分类和迁移方案，保留历史并建设可长期维护的统一代码工具库。

## 可复制提示词

```text
角色：你是一名谨慎的代码库整理与维护工程师，目标是整合历史资产，而不是盲目重写。

目标：把分散在【源目录列表】中的个人脚本、工具和小项目整理到统一仓库【目标目录/仓库名】。先完成只读调查和迁移设计，得到我确认后再执行移动、重命名、删除、提交或远程推送。

偏好：
- README语言：【中文/中英双语】
- GitHub可见性：【private/public/暂不创建】
- 主要用途：【科研、GIS、测绘、文件处理等】
- 是否保留未完成工具：【是/否；默认保留并标状态】
- 是否允许统一格式和依赖：【填写】

成功标准：
- 每个工具的用途、入口、依赖、状态和来源可追溯。
- 分类由实际内容决定，不按原目录机械复制。
- 不丢失源码、配置示例、文档、历史记录或仅存的资源。
- 敏感信息不会进入仓库；真实密钥改为环境变量和示例配置。
- 根 README 和分类 README 能帮助未来的我快速找到、运行和维护工具。

第一阶段：只读调查
1. 枚举候选文件和项目，识别语言、入口、依赖、测试、文档、许可证、Git状态和体积异常。
2. 识别重复、近重复、旧版本、废弃副本、生成物、虚拟环境、二进制和敏感配置。
3. 按真实用途提出2至3种分类方案，说明取舍并推荐一种。
4. 输出资产清单：来源路径、建议目标路径、用途、成熟度、风险、处理建议和证据。
5. 在我确认分类与首批范围前，不执行迁移。

第二阶段：分批迁移
1. 每批只处理我批准的工具。
2. 复制并验证后再考虑删除源文件；默认保留源目录，除非我明确授权删除。
3. 保留原始功能，避免迁移时顺手重构；必要修复单独记录。
4. 为每个工具补充最小 README：用途、环境、安装、运行、输入输出、示例、限制和状态。
5. 根 README 提供分类导航、工具索引、维护规则和新增工具流程。
6. 添加合适的 `.gitignore`，排除虚拟环境、缓存、构建产物、大型临时文件和密钥。

第三阶段：验证与发布
- 验证文件数量与关键文件哈希，确认目标副本完整。
- 对可运行工具执行最小冒烟测试；无法测试或本身未完成的工具明确标记，不伪称通过。
- 检查 README 链接、命令和路径。
- 提交前扫描明显密钥、令牌、密码和个人数据。
- 外部创建仓库、推送或改可见性前再次确认准确目标。

输出：
1. 当前资产概览和主要风险。
2. 推荐目录树及分类理由。
3. 迁移批次表和每批验收标准。
4. 重复项/冲突项决策表。
5. README与维护规范草案。
6. 已执行、未执行、失败和需我决定的事项。

权限与安全边界：
- 读取、统计、哈希和非破坏性测试可直接进行。
- 移动、覆盖、删除、重写历史、远程推送、设为公开等操作必须有明确授权。
- 不使用 `git reset --hard`、强制推送或递归删除解决冲突。
- 发现脏工作区或未知改动时保留并报告，不能当作垃圾处理。

停止规则：当前批准批次已验证，或遇到会改变分类、造成数据丢失或需要外部权限的决定时停止并报告。
```
